# 迷路遥控 — 小米手环 10 原生 BLE 遥控表盘

在小米手环 10（产品代号 o66cn，固件 3.1.28）的表盘 Lua 环境里加载一段自带的 ARM Thumb 常驻载荷，
由它直接使用固件蓝牙服务完成扫描、连接、GATT 读写与通知订阅，再通过共享内存把事件交回 Lua 界面。
界面按 212 × 520 药丸屏设计，用于双通道强度遥控。

- 目标固件：o66cn 3.1.28，SHA-256 `fb726472416e99ba11d1c20ce8f0d4f0831a6e9a673d63bb5918e2c3921d8845`
- 安装包：`dist/o66cn-3.1.28-native-ble-r8.bin`，表盘名称「迷路遥控」，ID `000000399920`
- 状态：本地仿真与断言测试全部通过。R3 已由用户在真机确认可以连接并完成读写，
  R4–R8 的触控、字体、长期连接与功耗仍待真机验证；逐版本记录见 [device-validation.json](device-validation.json)。

本仓库只包含成品：表盘 Lua 应用、原生桥接载荷、构建与测试工具。目标固件与模板表盘容器需要自行提供，
见「构建」。

## 功能

- 扫描与停止扫描，按地址去重，显示 RSSI 与设备名
- GATT 客户端：连接、断开、服务发现、属性查询
- 特征读取、带响应写入（最大 514 字节）、订阅与取消订阅
- 连接、断开、发现、读写、订阅结果与通知回调全部经共享内存回到 Lua
- 双通道 0–100 强度独立调节；「停止全部」同时归零
- 熄屏或临时隐藏表盘时保留已建立的连接，亮屏后恢复状态与近期通知
- 常驻载荷每个开机周期只创建一次，附着时校验代码、CRC、布局与堆边界

## 实现方案

### 加载链

表盘 Lua chunk → 同步 PIC 执行 → 常驻任务。

1. `lua/loader.lua` 在表盘 Lua VM 内运行：把载荷镜像写入一段由活跃 Lua 长字符串持有的内存，
   借固件 NSH 的 `mw` / `exec` 完成写入与执行，并执行数据缓存清理和指令缓存失效。
2. 镜像入口是 `native/entry.S` 的 `o66_entry`：保存控制寄存器和栈指针到 mailbox，
   检查线程模式、异常模式与栈对齐，然后调用 `o66_payload`。
3. `o66_payload` 用固件的零初始化分配器从 Umem 取一块内存，把完整 PIC 镜像与状态区复制进去，
   校验地址对齐与堆边界，写入 magic、版本、镜像大小和 CRC。镜像内 `ble_state()` 依赖的字面量
   被改写为状态区地址，此后副本只引用自己的状态区。
4. 通过 `nxposix_spawn` 创建独立任务 `o66_ble`（8 KiB 栈，优先级 100），引导程序随即返回；
   只有这份复制出来的内存会继续存活，任务也使用自己的 BLE instance 与 client。

### 原生桥接层

`native/bridge.c` 是唯一进入设备的原生代码。常驻任务注册 4 项扫描回调与 7 项 GATT 回调，
然后进入管理循环：

- **命令/应答**：Lua 写参数后发布请求序号；任务执行命令，记录错误码与代次，再发布应答。
  每个请求至多一个在途，共享状态保留到重启。
- **事件队列**：16 个 544 字节槽。回调生产者用无等待原子锁写入，Lua 读完才前移 tail；
  控制事件丢失是致命错误。
- **通知缓冲**：16 个 548 字节槽，与控制队列不共用锁。每槽先发布忙序号，填充后再发布偶序号，
  Lua 跨多次读取时核对前后序号，被覆盖或正忙则留到下次。通知是最近状态采样，不保证逐帧无损。
- **控制批次**：命令 11 提交两帧强度加三帧归零，命令 12 只提交三帧归零。任务每帧一次写入，
  收到固件写完成回调后推进；新批次可覆盖尚未发送的旧帧，但不能撤回已在途的写入。
  批次完成的判据是全部写回调成功，请求 ACK 只表示任务接受了批次。
- **生命周期**：前台心跳消失约 5 秒后请求停止并断开；后台标志为 1 时保留连接、请求停止扫描，
  管理轮询降到 1 秒。扫描约 10 秒自动停止，开始连接约 15 秒无回调则关闭。
  关闭时若曾接受控制命令，先发送保存的归零帧再断开。

### 共享内存 ABI

状态区布局、命令号、事件类型与回调表在 [docs/abi.md](docs/abi.md) 中逐字段列出，
偏移由 `bridge.c` 的 `_Static_assert` 固定，版本号 `0x10004`，总长 18872 字节。
Lua 侧只通过这份布局访问原生状态：所有回调数据在返回前复制，不保留回调时的临时指针。

### Lua 侧

| 文件 | 职责 |
|---|---|
| `lua/loader.lua` | 同步 PIC 加载与内存读写，含镜像 CRC 与固件版本检查 |
| `lua/transport.lua` | 共享内存传输：附着与复用、命令发送、事件与通知读取 |
| `lua/protocol.lua` | 设备命令帧的 12 字节编码与解码 |
| `lua/session.lua` | 会话状态机：扫描、连接、发现、属性分类、订阅、初始归零、控制批次 |
| `lua/display.lua` | 文本分页与 UTF-8 处理，供错误与帮助页面使用 |
| `lua/main.lua` | 表盘入口：页面、控件、触摸与生命周期事件 |

会话层按固件的属性类型分类：`0 PRI / 1 SND / 2 INC / 3 CHR / 4 DES`，只有类型 3 绑定为特征，
include 与 descriptor 会被跳过。

### 界面

212 × 520 药丸屏（上下半径 106，圆弧留 8 px 余量）：

- 首页只有居中的 180 px 圆形连接按钮与底部帮助；已连接时圆形按钮进入遥控。
- 遥控页左右各一条 64 × 174 px 竖向滑条，显示通道名称与强度，上滑增强、下滑减弱。
- 「停止全部」固定在中段同一位置；设备列表每页两台，帮助拆成连接、调节、熄屏三页。
- 拖动通过固件的输入设备绑定读取屏幕坐标，刷新时保留触摸对象并合并最新目标；
  停止、离页、触摸丢失与熄屏会取消拖动。

[三屏预览](dist/ui-preview-r8.png) 由布局快照加胶囊遮罩和替代字体渲染，不是真机截图。

### 安装包

`tools/watchface.py` 在已验证可安装的表盘容器上原地改写：保留全部资源表偏移，
把 5 个普通样式的 Lua 入口替换为同一段内联脚本，AOD 样式不启动脚本，表盘 ID 与标题写在容器头部。

## 构建

需要 Python 3.11+、Clang、LLD（`ld.lld`）与 Lua 5.4（含 `luac5.4`）。

两个输入不随仓库分发，请放入 `firmware/`，或用 `--firmware` / `--template` 指定：

| 文件 | 说明 | SHA-256 |
|---|---|---|
| `firmware/vela_ap.bin` | 目标固件中的 AP 载荷 | `fb726472416e99ba11d1c20ce8f0d4f0831a6e9a673d63bb5918e2c3921d8845` |
| `firmware/watchface-template.bin` | 模板表盘容器的 `resource.bin` | `5a065e845d4da2478e71f109789bfa1d5bf080b46393a121357045913253602c` |

```sh
python3 tools/build.py
```

构建校验固件 SHA-256，重新链接载荷，生成指令指纹、载荷 CRC、内联 Lua 与安装包，
并写出 `dist/manifest.json`。载荷须为纯 PIC：无 GOT、无 BSS、无可写静态数据，
大小 128–32768 字节，入口由通用汇编包装器提供。

## 安装与操作

用 AstroBox 安装 [dist/o66cn-3.1.28-native-ble-r8.bin](dist/o66cn-3.1.28-native-ble-r8.bin)，
表盘名称「迷路遥控」，仅适用于小米手环 10 / o66cn **3.1.28**。

1. 安装后开启设备，在首页点圆形「连接」。从 R5 或更早版本升级请先重启手环。
2. 在分页列表点选设备，等待连接与初始归零完成。
3. 左右滑条独立调节，滑到底部归零；「停止全部」同时归零两个通道。
4. 返回首页、打开帮助、切换页面都保留连接；熄屏后保持，亮屏同步状态与近期通知。
5. 结束时在「设备」页点「断开连接」。再次连接会重新确认归零，不恢复上次强度。

安装后原生载荷版本为 `0x10004`，**从更早版本升级需要重启手环一次**。

## 测试

```sh
lua5.4 tests/session.lua
lua5.4 tests/display.lua
lua5.4 tests/transport.lua
python3 tests/package.py
python3 tests/firmware.py     # 需要 Unicorn 与 firmware/vela_ap.bin
```

- `tests/firmware.py` 在 Unicorn 上执行真实载荷、固件包装器与回调派发，覆盖属性类型分支、
  两处地址重定位、独立任务入口参数、client 所有权、请求封包、扫描 cookie 释放、514 字节数据、
  队列溢出与分配失败，以及 host Lua → 原始固件 → PIC → 回调队列 → Lua 的联调。
- 联调用例把载荷实际发出的密文帧交给独立实现解析，核对通道与数值。
- Lua 断言测试覆盖会话状态机 69 项、界面与布局 780 项、传输并发 20 项。

界面预览可以由布局快照重建（需要 Pillow 与中文字体，可用 `--font` 指定字体文件）：

```sh
lua5.4 tests/display.lua /tmp/o66-ui.json
python3 preview.py /tmp/o66-ui.json
```

## 已知限制

- 仿真建模调度、Umem 分配、蓝牙服务 IPC 与无线事件，不能证明真实缓存一致性、蓝牙服务实际响应、
  无线兼容性、后台耗电或真机熄屏稳定性；manifest 中的 `NOT_PROBED` 保留这一界限。
- 通知通道提供最近状态采样，不保证逐帧无损；需要完整时序的协议不应把它当作无损事件流。
- 停止指令不构成物理保证：无线链路已断开或固件 IPC 阻塞时无法确认设备已归零。
- 真机字体渲染、触摸手感与长期功耗仍待验证。
- 常驻载荷保留到重启；主动断开或销毁表盘会停止扫描并断开连接，但已分配的内存不回收。

## 版本历史

| 版本 | 变更 |
|---|---|
| R8 | 首页只保留居中圆形连接按钮与底部帮助；遥控页改为左右双通道竖向滑条，取消独立通道页。 |
| R7 | 按药丸屏边界计算控件宽度与触控高度，放大强度数字，帮助拆分页面，每页两台设备。 |
| R6 | 多级遥控界面、双通道调节、原生停止批次；属性 ABI 升级为 `0x10004`。 |
| R5 | 熄屏保留连接：后台标志暂停前台租约但保留连接与订阅，亮屏恢复心跳后再消费积压事件。 |
| R4 | 通知单独使用循环缓冲，与控制队列隔离；连续 75 帧突发不再丢写完成回调。 |
| R3 | 修正属性类型分类（特征为 3），读写与通知句柄正确绑定；错误文本按页显示。 |
| R2 | 改用真实零初始化分配器路径，修复扫描时的队列索引损坏。 |

逐版本的用户反馈、安装包哈希与回归结果见 [device-validation.json](device-validation.json)。

## 触摸接口说明

界面不使用固件的滑条构造器，而是用常驻对象绘制轨道、填充与滑块，并监听
PRESSED / PRESSING / RELEASED / PRESS_LOST。坐标读取所用的绑定见
[docs/lua-input-abi.md](docs/lua-input-abi.md)。
